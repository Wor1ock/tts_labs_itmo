**Лабораторная работа №2. Просодика**

**Цель работы:** Разработка модуля прогнозирования мест и длительности пауз по тексту на русском языке

**Краткое описание:** В рамках настоящей работы необходимо ознакомиться с пословной сегментацией данных из дейтасета "RUSLAN", изучить распределение длительности пауз в наборе данных, провести анализ качества сегментации, и разработать модуль предсказания мест и длительности пауз по тексту.

**Суть проблемы**: Просодика -- крупный раздел лингвистики, отвечающий за дополнительные невербальные характеристики реализации речи, способные нести самостоятельный смысл. К наиболее важным характеристикам можно отнести мелодику (управление интонацией) и паузацию (расстановка пауз и деление потока речи на осмысленные самостоятельные части). И мелодика и паузация частично управляются знаками препинания и смыслом предложения, но сохраняют при этом большой простор для различных интерпретаций, а пользователям синтеза речи зачастую нужны более точечные методы управления просодикой. Часть функций по моделированию просодики акустическая модель может взять на себя, но зачастую требуется корректировать её поведение. В рамках настоящей работы предлагается разработать систему прогнозирования мест и длительности пауз по тексту, которая позволит пользователю системы точечно управлять длительностью синтезируемых фраз при желании.

### 3. Подготовьте данные для обучения модуля предсказания пауз

Воспользуйтесь `data/metadata_RUSLAN_22200_normalized.csv` в качестве источника данных и подготовьте данные для обучения модуля предсказания пауз. В рамках этой задачи также предстоит провести *токенизацию*, то есть разделение текста на текстовые единицы-токены. Токенизация нужна для того, чтобы понять, после какого именно слова должна быть пауза.
Предлагается использовать таблицу (дейтафрейм) следующего формата для обучения и тестирования модуля предсказания пауз:

| Поле| Тип | Смысл |
|---|---|---|
| `id` | `string` | Индекс предложения из исходной базы|
| `label` | `string` | Нормализованный текст токена -- получается из .TextGrid, или `""` для паузы |
| `label_raw` | `string` | Сырой текст токена -- получается из колонки `nrm` -- или `<SIL>` для паузы; включает в себя всю пунктуацию до следующего буквенного токена |
| `duration` | `float` | Длительность токена в секундах |
| `is_last_word` | `int` | Является ли данный токен последним словом в предложении (1 -- является, 0 -- не является; финальная пауза не считается)  |
| `is_pause_after` | `int` | Есть ли пауза после данного токена (`1` -- есть, `0` -- нет) |
| `pause_duration` | `float` | Длительность паузы, следующей за данным токеном: `0.0`, если паузы нет, число в секундах, если есть |
| `set` | `string` | Метка подвыборки: `train` или `test`. Для упрощения сравнения результатов экспериментов между студентами, предлагается явно зафиксировать обучающие и тестовые данные. Правило выделения тестовых данных: идентификатор аудио в базе RUSLAN делится нацело на 5 (то есть оканчивается на 0 или 5): это даёт деление примерно в 80%-20%. `test` выборку можно использовать только для финальной оценки алгоритмов: для валидации используйте поднабор `train` выборки. |

Поля `duration`, `label`, `label_raw` будут очень полезны для анализа данных; поля `is_last_word`, `is_pause_after`, `pause_duration` -- очень полезны на этапе построения классификатора.

В данной структуре предполагается, что токены идут в том порядке, в котором они были в предложении; Если перемешать или отсортировать токены, то эта информация пропадёт, и потребуются дополнительные метки.

Пример скрипта подготовки данных в ожидаемом виде: `labs/lab2_pauses/prepare_training_data.py`

### 4. Разработайте предиктор пауз

Необходимо разработать класс, который принимает на вход последовательность токенов, и предсказывает необходимость постановки паузы после каждого токена в последовательности, и её длительность.

Для обучения и валидации используйте `train`-множество, для тестирования -- `test` множество. Допустимо отфильтровать нерелевантные/плохо размеченные примеры из `test` множества, если будет показано низкое качество разметки на этапе анализа.

Для обучения и тестирования модели рекомендуется не использовать последнюю паузу в предложении (т.е. паузу после токена с `is_last_word==1`), поскольку такие паузы попадают на стык аудиофайлов во время процедуры записи, и не могут считаться релевантным источником для оценки длительности пауз в естественной речи.

Решение по предсказанию мест пауз и по предсказанию длительности пауз можно сделать отдельными методами, но PausePredictor должен агрегировать их.

Подходы к решению задачи:
- Системы основанные на правилах и парсинге знаков препинания (бейзлайн)
- Семантическая векторизация слов (эмбеддинги, векторы и.т.д.) + классические/DNN подходы
- Морфологические и синтаксические признаки + классические/DNN подходы
- Sequence2Sequence подходы

Целевые метрики:
* F1-мера ≥ 0.8 для метки `is_pause_after` на `test`-части;
* Средняя ошибка (`Mean Absolute Error`) ≤ 0.1 (то есть среднее отклонение меньше 100 миллисекунд) для метки `pause_duration`, но только на тех токенах, которые имеют паузу в оригинале, и для которых пауза предсказана предиктором (То есть рассматриваем только True Positive примеры)

Интерфейс-заглушка класса а также код для тестирования качества приложен в `labs/lab2_pauses/pause_predictor.py`

**Результат этапа:** Реализован класс предиктора в `labs/lab2_pauses/pause_predictor.py`

### 1. Улучшение разметки
Текущая разметка несмотря на версию v2 имеет определенное количество известных проблем, и неопределенное количество неизвестных. Важное замечание: кроме разметки по времени для дальнейшей работы также будет очень важна разметка по фонемам.

При выполнении данной задачи добавьте в отчет результат анализа вашей версии разметки и сравнения её с бейзлайном.

Для решения задачи обучения модели предсказания пауз мы можем использовать деление на токены по результатам выравния инструментом MFA. Однако при использовании в системе синтеза речи, процедура токенизации также потребуется, и наивный подход "делить токены по пробелу" может оказаться субоптимальным. Проверьте работоспособность такого подхода в рамках набора данных RUSLAN и сравните с токенизацией от MFA.
